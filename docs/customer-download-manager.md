# 客户下载管理

客户点击单张、已选照片或全部下载后，打开右下角“下载管理”。照片逐文件接收，不打 ZIP 包；分辨率选择仍然有效。

## 如何使用

1. 在“进行中”查看文件名、文件版本、已接收大小及进度，可暂停、继续或取消。
2. 新任务接收完成后会提示并自动交给浏览器保存；浏览器可能要求确认。若未保存，可点击“保存文件/再次保存”；手动保存仍可使用系统分享。显示“已交给浏览器保存”不代表系统已确认落盘。刷新页面不会自动重新保存历史文件。
3. 网络中断会自动有限重试；仍失败时可手动继续。刷新或重开同一浏览器后，继续接收尚未完成的部分。
4. “历史记录”可查看同一项目、同一客户身份在不同设备的下载尝试；另一设备重新下载从零开始。

## 身份与设备

跨设备须选择同一个已有客户身份；同名新身份不会自动合并。现有邀请仍然一次性使用，不改变原有邀请规则。匿名客户可以下载，但仅保留当前浏览器记录。客户身份沿用现有相册访问机制，不新增独立账号认证。

文件分块仅保存在当前站点、当前浏览器的 IndexedDB。更换地址、设备、浏览器、清理站点数据或隐私窗口关闭，可能丢失本地续传内容；服务器历史不会替代这些文件字节。不同设备的下载进度分开记录。

## 续传边界

- 最多同时接收两个文件，按 4 MiB 确认分块；断线时未完成的当前分块重新接收。
- 每个分块最多尝试三次；关闭页面会停止下载。异常退出后浏览器任务锁最长约90秒释放。
- 文件替换后版本变化，必须重新下载，不能拼接新旧内容。
- 每次读取仍检查项目、照片、分类、身份及下载权限。历史不提供绕过权限的下载入口。
- 存储不足或不可用时明确提示，可主动选择普通下载；普通下载不提供本管理器的续传与进度。
- 清除本地文件保留任务历史；取消和离线状态更新会保留待同步记录。

## 服务端运维

历史在应用数据库中保存，随现有 SQL 备份；客户删除、匿名化、合并和项目永久删除同步处理相关记录。不可变下载缓存位于应用存储 cache/customer-downloads，按请求触发清理，保留期限24小时、保留文件总量上限2 GiB；并发生成临时文件时峰值可能更高。缓存不是原片，清理后会按实际版本重新准备。
