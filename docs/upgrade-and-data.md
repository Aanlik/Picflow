# 运行架构与升级边界

Picflow 是一个固定版本的 Docker 镜像。容器内包含客户选片与摄影师工作台，以及仅监听容器回环地址的精修同步进程。Bridge 状态与 Picflow 应用状态分别保存在独立数据卷中。

## 持久数据与 NAS 挂载

- `/data`：Picflow 数据库、上传文件、预览、缩略图、归档及应用配置。
- `/bridge-data`：精修流程数据库、项目绑定、交付版本和待恢复任务。
- `/external-media/Camera`：NAS 原片与样片目录，只读挂载。
- `/delivery`：NAS 精修交付根目录，可写挂载；Picflow 为每个已关联项目创建独立工作区。

部署或更新时保留两个应用数据卷和 NAS 原片。不要把空卷当作旧数据卷，也不要给 Camera 写权限。项目删除、归档或同步异常的处理范围以 README 的工作流说明为准。

## 升级和回退

数据库和 Bridge 状态采用向前迁移。升级前停止旧容器，备份两个应用数据卷与项目交付目录，并确认备份可读取。升级后先检查健康状态、项目照片、选片进度和交付版本，再继续工作。

如需回退，恢复升级前相互匹配的数据库、Bridge 状态和交付目录备份；仅切换到旧镜像可能导致流程状态与照片版本不一致。恢复期间应暂停同步，核对项目、照片编号、客户反馈和交付记录后再恢复工作。

## 分支和发布

`main` 是主线和正式发布分支，`dev` 用于日常开发。统一工作流在两条分支和 PR 上运行前后端、中文、Bridge、容器及照片流程检查；正式镜像只能从 `main` 手动发布。Picflow 不自动合并或跟随上游代码。

代码来源和许可追溯见[代码来源记录](source-provenance.md)，部署命令与目录准备见[README](../README.md)。
